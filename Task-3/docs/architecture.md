## 2. Data flow / pipeline

1. **Data generation** (`src/generate_data.py`): produces a reproducible
   synthetic catalogue of 300 movies (title, year, genres, plot overview)
   and 200 synthetic users with biased genre preferences, generating
   roughly 10,000 ratings. A fixed random seed (42) makes results
   reproducible across machines.

2. **Loading & pre-processing** (`src/data_loader.py`): reads the CSVs,
   drops duplicate movie ids, fills missing text fields, and builds a
   combined "content soup" text field (genres repeated + overview) used
   as the input to the TF-IDF vectorizer.

3. **Content-based model** (`src/content_based.py`):
   - Vectorizes the content soup with `TfidfVectorizer` (unigrams +
     bigrams, English stop-words removed).
   - Computes a full movie-by-movie cosine similarity matrix once at
     start-up.
   - Serves two query types: "similar to this title" and "best matches
     for these genres".

4. **Collaborative-filtering model** (`src/collaborative_filtering.py`):
   - Pivots the ratings table into a user x movie matrix.
   - Mean-centers each user's ratings (removes individual rating-scale
     bias) then factorizes the matrix with `TruncatedSVD` to predict
     ratings for unseen (user, movie) pairs.
   - Also supports item-based nearest-neighbour lookups ("movies rated
     like this one") via cosine similarity between movie rating vectors.

5. **Recommender facade** (`src/recommender.py`): a single
   `MovieRecommender` class that both the console app and the Streamlit
   app import, exposing a small, stable public API and a hybrid mode
   that blends normalized collaborative and content-based scores.

6. **Evaluation** (`src/evaluation.py`): holds out 20% of ratings to
   compute RMSE/MAE and Precision@K/Recall@K for the collaborative
   model, measures intra-list genre coherence for the content-based
   model, and times model build + per-query latency for both. Results
   are written to `docs/performance_report.md`.

7. **User interfaces**:
   - `src/console_app.py`: a menu-driven interactive shell (no
     external UI dependency).
   - `app.py`: a tabbed Streamlit dashboard exposing every
     recommendation mode with a graphical, non-technical UI.
   - `notebooks/movie_recommendation_engine.ipynb`: a narrated,
     step-by-step notebook covering data loading, EDA, model building,
     evaluation and live demo queries — the primary deliverable for
     reviewers who want to see the reasoning, not just the final code.

## 3. Why these design choices

- **TruncatedSVD over the `surprise` library**: `surprise` requires a
  C/Cython build step that is fragile across environments; `TruncatedSVD`
  ships with `scikit-learn`, which is already a hard requirement, and
  gives the same latent-factor matrix-factorization idea taught in most
  recommender-systems courses.
- **Synthetic dataset with genre-biased users**: real-world datasets
  (e.g. MovieLens) require an external download at run time. Generating
  a reproducible synthetic dataset with realistic structure (genre
  correlations, biased user tastes) keeps the whole project
  self-contained, offline-friendly, and fast to demo, while still giving
  both models real signal to learn from.
- **Facade pattern (`MovieRecommender`)**: keeps the console and web UIs
  thin — all recommendation logic lives in `src/`, so both interfaces
  stay in sync and unit tests only need to target one layer.
